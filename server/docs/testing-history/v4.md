# V4 Test Results

## Summary

`v4` is the rate-limit-focused verification suite.

Its purpose is to isolate rate-limit behavior instead of mixing those checks into the broader `v2` business-flow regression suite.

## Coverage

`v4` currently verifies:

- global rate limiting on non-exempt API routes
- login exemption from the global limiter while login-specific behavior still applies
- refresh exemption from the global limiter while refresh-specific behavior still applies
- separate limiter buckets for different client IPs
- fail-open behavior when the Redis-backed limiter path degrades

## Why V4 Matters

`v4` gives a dedicated place to verify behavior that depends on:

- Redis availability
- trusted client IP handling
- global limiter boundaries
