# v3 test results

## Summary

`v3` is the migration-focused verification suite.

Its purpose is to prove that the new migration workflow works correctly without turning `v3` into a duplicate of the broader `v2` regression suite.

## Coverage

`v3` currently verifies:

- baseline migration can build the full managed schema from an empty database
- migration tracking is recorded correctly in `pgmigrations`
- expected migration-managed indexes exist after schema build
- RBAC reference seed works on top of the migrated schema
- RBAC reference seed is idempotent
- rerunning `migrate:up` after the baseline is applied is a no-op
- migrated schema still supports bootstrap registration, login, session creation, audit logging, and authenticated protected-route access

## Verified result

Latest verified result:

- date: `2026-04-14`
- command: `pnpm run test:v3`
- outcome: `4 passed, 0 failed`

## Why v3 matters

`v3` gives confidence in the migration layer specifically.

It proves:

- the schema can now be created from migration history instead of only from destructive reset code
- the seed workflow is compatible with that migrated schema
- the resulting database still behaves correctly for core auth and RBAC bootstrap flows

## Relationship to v2

- `v2` remains the active broad regression suite
- `v3` is narrower and purpose-built for migration verification
- after migration implementation, `v2` was also rerun successfully as regression confirmation, with `21 passed, 0 failed`
