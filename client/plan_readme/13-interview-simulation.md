# 13. Interview simulation (hub)

This is a **two-part practice scenario**: you use it to rehearse how you would **pitch this repo in an interview**, then read how a **senior engineer might react** after hearing that pitch.

**How to use it**

1. Read [**Part 1 — Candidate**](./14-interview-part1-candidate.md) out loud or summarize it in your own words. That is “you” in the room.
2. Read [**Part 2 — Senior reviewer**](./15-interview-part2-senior.md) as the interviewer’s internal notes: score, feedback, follow-up topics.

**Supporting technical docs** (for facts while you practice)

- [01 — Architecture Overview](./01-architecture-overview.md)
- [06 — Code Patterns, Strengths & Weaknesses](./06-patterns-strengths-weaknesses.md)
- [07 — React Query](./07-react-query.md) through [12 — OpenAPI TypeScript contract](./12-openapi-typescript-contract.md)

---

## Parts

| Doc | Role |
|-----|------|
| [14 — Part 1 (candidate)](./14-interview-part1-candidate.md) | Resume angle, strengths, honest gaps, how you explain backend vs frontend, where to point in the repo |
| [15 — Part 2 (senior)](./15-interview-part2-senior.md) | Reaction after Part 1, **score out of 10**, strengths, probes, verdict |

This is not a real interview grade — it is a **rehearsal aid** for positioning the project clearly and calmly.
